§ O que a aplicação faz

Síntese da análise produzida pelo agente analista (analise-agente.json).

Aplicação Flex de agenda de contatos (CRUD) que consome uma API REST/JSON (/contatos) via HTTPService. Tela única com busca, grid de contatos (DataGrid) à esquerda e formulário de edição/criação à direita (nome, telefones, e-mails, endereço). Permite listar com filtro, selecionar um contato na grade para editar, adicionar/remover telefones e e-mails em listas locais antes de salvar, criar, atualizar e excluir contatos (com confirmação via Alert). A comunicação é encapsulada na classe ApiClient, que usa truques de compatibilidade com Flash (POST com _method=PUT/DELETE, suppress_response_codes, _ts anti-cache).

Decisões de conversão

  • baseUrl da API fixado em 'api' (FlexGlobals não existe no Royale).
  • mx:Panel → j:Card com j:CardHeader(html:H4) + j:CardPrimaryContent; mx:ControlBar → j:CardActions.
  • mx:HDividedBox → j:HGroup com larguras 55%/45% e sem altura fixa.
  • Título dinâmico do Panel virou variável [Bindable] tituloFormulario recalculada em atualizarEstado().
  • enabled='{…}' substituído por bead j:Disabled ligado a ocupado/excluirDesabilitado.
  • rowCount='3' das j:List virou altura fixa (90px) e largura fixa (220px).
  • maxChars, toolTip, setFocus(), scrollToIndex() removidos.
  • required='true' virou asterisco no label: "Nome *".
  • Alert.show com handler virou new Alert() + AlertModel + CloseEvent.CLOSE.
  • new Date().time → new Date().getTime() no parâmetro anti-cache _ts.
Pendências assumidas (avisos): os toolTip de busca/telefone/e-mail foram removidos (sem bead equivalente) e não há mais divisor arrastável entre grid e formulário (era mx:HDividedBox).

§ Conclusão

A migração foi executada de ponta a ponta em 200 segundos com zero avisos finais. O pipeline automatizado:

  • Compilou o Flex original como baseline de referência.
  • Analisou 524 linhas de MXML/AS3 e mapeou 16 componentes MX → Jewel.
  • Reescreveu os dois arquivos para royale/src/, preservando 30 funções e o contrato REST.
  • Recuperou automaticamente 1 erro de compilação (gap em j:Form) via agente assistente.
  • Empacotou o projeto HTML5 com nginx + Docker, apontando para o backend Java 7 existente.
  • Validou 6 chamadas REST contra o backend, incluindo o _method override e o formato de erro.
Resultado final: aplicação HTML5 (index.html + Agenda.js + Agenda.min.css) funcionalmente equivalente ao Flex original, sem dependência de Flash e reutilizando o backend Java 7 sem qualquer alteração no contrato da API.

Pendências conhecidas (não bloqueantes)

  • toolTip dos campos de busca/telefone/e-mail removidos (sem bead equivalente em Jewel).
  • Divisor arrastável entre grid e formulário removido (mx:HDividedBox não tem equivalente).
